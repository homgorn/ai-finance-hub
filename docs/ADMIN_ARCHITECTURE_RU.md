# Admin/User Admin Architecture (RU)

Да, лучше делать **две админки (или два role-based интерфейса)**:

## 1) Platform Admin (внутренняя)
Для владельца/операторов:
- управление тенантами,
- квоты/бюджеты,
- аудит/события,
- управление skill/policy,
- мониторинг и инциденты.

## 2) Tenant/User Admin (клиентская)
Для клиентов/команд:
- управление своими пользователями,
- просмотр своих задач и отчетов,
- локальные настройки и лимиты в пределах tenant.

## Почему разделять
- Безопасность (минимум привилегий)
- Меньше риска случайных критических изменений
- Проще комплаенс и аудит

## Роли (рекомендация)
- `platform_owner`
- `platform_operator`
- `tenant_admin`
- `tenant_analyst`
- `end_user`

## Технический подход
- RBAC + tenant isolation
- Feature flags по ролям
- Audit trail на административные действия
